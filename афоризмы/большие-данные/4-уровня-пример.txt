5 V's of Big Data:

Big Data = Volume × Velocity × Variety × Veracity × Value

где:
Volume — объём данных (терабайты, петабайты)
Velocity — скорость генерации и обработки
Variety — разнообразие типов данных (structured, unstructured, semi-structured)
Veracity — достоверность и качество данных
Value — ценность, извлекаемая из данных

Масштаб обработки:
Scalability = Performance(n × nodes) / (n × Performance(1 node))

→ Идеально: линейное масштабирование (Scalability = 1)
→ Реально: субlinear из-за координации и сетевых overhead

CAP Theorem (для распределённых систем):
Можно выбрать только 2 из 3:
• Consistency (Согласованность): все узлы видят одни и те же данные
• Availability (Доступность): каждый запрос получает ответ
• Partition tolerance (Устойчивость к разделению): работа при сетевых сбоях

→ На практике: нужна P (partition tolerance)
→ Выбор: AP (eventual consistency) vs CP (strong consistency)

MAPREDUCE ПАРАДИГМА (классический паттерн):

Задача: подсчитать частоту слов в огромном корпусе текстов

```
INPUT: миллиарды строк текста

MAP phase (параллельно):
  • Каждый mapper обрабатывает часть данных
  • Разбивает текст на слова
  • Выдаёт пары (word, 1)
  
  Input: "hello world hello"
  Output: [("hello", 1), ("world", 1), ("hello", 1)]

SHUFFLE phase (автоматически):
  • Группировка по ключам
  • Все значения для одного ключа попадают к одному reducer
  
  After shuffle: 
    "hello" → [1, 1]
    "world" → [1]

REDUCE phase (параллельно):
  • Каждый reducer агрегирует значения для своих ключей
  • Суммирует counts
  
  Output: [("hello", 2), ("world", 1)]

OUTPUT: частоты всех слов
```

Масштабируемость:
• 1 TB данных, 100 машин → каждая обрабатывает 10 GB
• Fault tolerance: если машина падает, задача переназначается
• Locality: обработка данных там, где они хранятся (избегаем network transfer)

ОБЪЯСНЕНИЕ:

АНАЛОГИЯ С НЕФТЬЮ:
• Сырая нефть бесполезна → нужна переработка
• Сырые данные бесполезны → нужна обработка и анализ

НО ОТЛИЧИЯ:
• Нефть — конечный ресурс, данные — растут экспоненциально
• Нефть теряет ценность при использовании, данные — нет
• Больше нефти = лучше, больше данных ≠ обязательно лучше

ПРОБЛЕМА:
90% данных в компаниях:
• Не структурированы
• Не каталогизированы
• Не доступны для анализа
• Просто занимают место

"Data hoarding" вместо "Data utilization"

РЕШЕНИЕ:
• Data governance: управление жизненным циклом данных
• Data quality: "garbage in, garbage out"
• Data culture: использование данных для решений
• Focus on value: не все данные нужно хранить

ПРЕДЫСТОРИЯ:

2003: Google публикует две статьи:
• Google File System (GFS)
• MapReduce

Описывают, как Google обрабатывает петабайты данных для поискового индекса.

2006: Doug Cutting (Yahoo) + Mike Cafarella
• Создают open-source реализацию: Hadoop
• Название: игрушечный слон сына Дуга
• Apache проект

ПРОБЛЕМА, КОТОРУЮ РЕШАЕТ HADOOP:

Традиционный подход:
• Scale-up: покупай больший сервер
• Дорого: enterprise hardware
• Ограничено: физические лимиты одной машины

Hadoop подход:
• Scale-out: добавляй больше обычных серверов (commodity hardware)
• Дешево: тысячи дешёвых машин вместо одной дорогой
• Неограниченно: просто добавляй узлы

АРХИТЕКТУРА HADOOP:

HDFS (Hadoop Distributed File System):
• Файлы разбиваются на блоки (128 MB)
• Блоки реплицируются на 3 узла (fault tolerance)
• NameNode: metadata, где какой блок
• DataNodes: хранят блоки

MapReduce:
• Map: обработка данных параллельно
• Reduce: агрегация результатов
• Framework автоматически:
  - Распределяет задачи
  - Обрабатывает ошибки
  - Оптимизирует locality (данные рядом с вычислениями)

ADOPTION:

2008-2012: Взрывной рост
• Yahoo: крупнейший deployment (42,000 узлов)
• Facebook: data warehouse на Hadoop (Hive)
• LinkedIn: recommendation engine
• Twitter: analytics platform
• Десятки других компаний

2010-2015: Hadoop Ecosystem
Hadoop стал платформой:
• Hive: SQL на Hadoop
• Pig: скриптовый язык
• HBase: NoSQL база данных
• Spark: замена MapReduce (10-100x быстрее)
• Kafka: streaming
• Zookeeper: координация

Cloudera, Hortonworks, MapR:
• Commercial distributions
• Enterprise support
• Интеграция и инструменты

ЗАКАТ HADOOP:

2015-2020: Cloud Native Era
• AWS, GCP, Azure предлагают managed services
• Serverless: не нужно управлять кластерами
• Separation of compute and storage: S3 + EMR
• Easier to use: меньше операционной сложности

Проблемы Hadoop:
• Операционная сложность: нужна команда админов
• Batch-oriented: плохо для real-time
• Legacy tech: MapReduce морально устарел (Spark лучше)

2020-настоящее: Hadoop → Cloud
• Cloudera + Hortonworks merger (2019), затем IPO failure
• Компании мигрируют с on-prem Hadoop на cloud
• Hadoop не умер, но больше не "hot tech"

НО: LEGACY ВАЖЕН
• Концепции остались: distributed computing, fault tolerance
• MapReduce парадигма влияла на всё: Spark, Flink, Beam
• HDFS идеи в S3, GCS, Azure Data Lake

LESSON:
Технологии меняются, но принципы остаются.

Hadoop демократизировал Big Data:
• До Hadoop: только Google, Yahoo могли обрабатывать петабайты
• После Hadoop: любая компания может scale-out
• Открыл эру Big Data

"Hadoop не умер, он просто эволюционировал в облако"

LESSON:
Big Data — это инструмент, который может использоваться во благо и во зло.

Необходимость:

• Consent: явное разрешение
• Regulation: правительства должны защищать граждан
• Ethics: компании должны саморегулироваться

"С большими данными приходит большая ответственность"

ПРАКТИЧЕСКИЕ РЕКОМЕНДАЦИИ:

1. ДЛЯ DATA ENGINEERS:

   Инфраструктура:
   • Начните с облака (AWS/GCP/Azure), не on-prem Hadoop
   • Используйте managed services (меньше операционной нагрузки)
   • Separation of concerns: storage отдельно от compute
   
   Pipeline design:
   • Idempotent: повторный запуск не ломает данные
   • Monitoring: логи, метрики, алерты
   • Data quality checks: валидация на каждом шаге
   • Incremental processing: не пересчитывать всё каждый раз
   
   Tools:
   • Airflow/Prefect: orchestration
   • dbt: SQL transformations
   • Great Expectations: data quality
   • Spark: для больших объёмов

2. ДЛЯ DATA SCIENTISTS:

   Работа с большими данными:
   • Sample first: работайте на sample локально, потом масштабируйте
   • Columnar formats: Parquet вместо CSV (10x быстрее)
   • Partitioning: partition by date/region для быстрых queries
   • Pushdown predicates: фильтруйте раньше, агрегируйте позже
   
   SQL optimization:
   • EXPLAIN PLAN: понимайте, что делает query
   • Избегайте SELECT *, выбирайте только нужные колонки
   • WHERE перед JOIN
   • Используйте indexes и partitions
   
   Scaling ML:
   • Feature engineering на Spark
   • Distributed training: Horovod, Ray
   • Model serving: deploy отдельно от training

3. ДЛЯ БИЗНЕСА:

   Data strategy:
   • Data-driven culture: решения на основе данных, не интуиции
   • Invest in data platform: это фундамент
   • Hire talent: data engineers, scientists, analysts
   
   ROI:
   • Начните с business case: какая проблема решается?
   • Измеряйте value: revenue, cost savings, efficiency
   • Quick wins: покажите ценность быстро
   
   Governance:
   • Data catalog: что за данные, где они
   • Access control: не все должны видеть всё
   • Compliance: GDPR, CCPA, industry regulations
   • Ethics: установите принципы использования данных

4. ДЛЯ ОБЩЕСТВА:

   Privacy:
   • Понимайте, какие данные о вас собираются
   • Используйте privacy tools: ad blockers, VPN
   • Читайте privacy policies (или хотя бы summary)
   • Exercise your rights: request data, delete data (GDPR)
   
   Critical thinking:
   • Correlation ≠ Causation
   • Algorithms have biases (от данных и создателей)
   • "Data-driven" ≠ объективный
   • Спрашивайте: чьи интересы представляют эти данные?

ЗАКЛЮЧЕНИЕ:

Big Data изменил мир. От того, как мы делаем покупки, до того, как выбираем 
лидеров. Данные — это действительно "новая нефть", но с уникальными свойствами.

КЛЮЧЕВЫЕ ИНСАЙТЫ:

1. Масштаб изменил игру:
   → Невозможно обрабатывать на одной машине
   → Распределённые системы — необходимость
   → Облачные решения демократизировали доступ

2. Данные ≠ Информация ≠ Знания:
   → Собирать легко, извлекать ценность — сложно
   → 90% данных не используются
   → Focus on business value, не на технологии

3. Этические вопросы критичны:
   → Privacy vs Personalization
   → Consent и transparency
   → Potential for manipulation
   → Необходимость регулирования

4. Технологии эволюционируют:
   → Hadoop → Cloud → Serverless
   → Batch → Streaming → Real-time
   → SQL → NoSQL → NewSQL
   → Но принципы остаются

Будущее Big Data — это баланс между инновациями и ответственностью,
между персонализацией и приватностью, между эффективностью и этикой.

"Данные — это линза, через которую мы видим мир. 
Важно помнить, что линзы могут искажать."
